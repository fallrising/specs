# 探索與推理體驗

具體場所、操作、線索及顯示期望引用 [scenarios.yaml](../data/scenarios.yaml)。

### REQ-EXP-01 線索有可完成的取得路徑與持續回看紀錄

玩家依場所調查或訪談取得已存在的線索。取得條件不得循環依賴、永久錯過或要求先猜中兇手；取得後能依出處與案件時刻回看原命題。偵查順序不改寫案件時間線。

- 里程碑：M1
- 優先：必要

#### AC-EXP-01 所有必要線索都能由公開調查行動取得

- Given 基準案件與 `acquisition_routes` 的探索路徑
- When 玩家依各路徑從開場走訪、調查及訪談
- Then 每條路徑均能取得 `evidence_sets.complete` 指定線索；取得時刻與順序可以不同，但內容、真相及判定一致，且不要求預先提交兇手
- 驗證：自動

#### AC-EXP-02 離開場所後仍可核對完整證據

- Given 玩家已取得 `review_fixture.evidence_ids` 並離開來源場所
- When 開啟證據紀錄並選擇各項證據
- Then 可見資料要求的來源、取得方式、關聯時間、原命題與可靠性類別，證詞不混為可靠記錄，重看不會丟失或新增命題
- 驗證：自動

### REQ-EXP-02 提交結論須區別猜中與已被證據支持

玩家可提交候選兇手及引用證據。判定只使用玩家引用且已取得的可靠證據，不讀取真相（`submission_rules`）。提交不自動揭露尚未取得的資訊；資訊不足、矛盾、指控不成立及已支持的結果分別呈現。揭曉前不得透露指控對象是否就是真兇：真兇與其他仍可行的嫌疑人得到相同的未證明狀態。主動揭曉後才能查看真相及排除其他候選人的說明，並可把先前的提交標註為猜中。

- 里程碑：M1
- 優先：必要

#### AC-EXP-03 答案正確但證據不足仍不算證明

- Given `submission_fixtures.correct_guess_without_proof`
- When 玩家提交資料中指定角色與目前已取得的證據
- Then 顯示資料中的未證明狀態，不宣稱通關證明、不洩漏缺少線索內容，且與 `other_feasible_suspect_same_status` 指控另一名仍可行嫌疑人時的狀態相同；`excluded_suspect` 顯示指控不成立；補齊完整集合後再次提交才可得到已支持結果，「猜中」的標註只在揭曉後出現
- 驗證：自動

#### AC-EXP-04 主動揭曉才呈現真相與可核對排除理由

- Given 完整基準案件且玩家尚未要求揭曉
- When 先檢視提交結果，再主動選擇揭曉
- Then 揭曉前維持取得資訊邊界；揭曉後顯示 `reveal_fixture` 指定的真實犯罪、路徑及排除理由，所引用證據能回到原紀錄
- 驗證：自動

### REQ-EXP-03 模板文字忠於事實與可信性

第一版所有敘事、證據與揭曉文字以事實欄位及固定模板表達。句型可以調整，但不能新增可供推理的命題；翻譯、改寫及錯誤訊息也不得把不確定說法變成已確認事件。

- 里程碑：M2
- 優先：必要

#### AC-EXP-05 顯示文字逐項對照既有命題

- Given `text_fidelity` 的模板、允許命題及禁止新增類型
- When 檢視基準與共謀情境的全部玩家文字
- Then 每句可影響推理的文字均能對照既有命題，時間、人名、地點與可靠性未改變；owner 確認沒有暗示未提供的世界事實
- 驗證：人工確認
