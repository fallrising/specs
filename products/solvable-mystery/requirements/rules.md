# 案件規則

所有人物、數值、證據與期望均引用 [scenarios.yaml](../data/scenarios.yaml)。本檔 AC 是待參考實作驗證的草案。

### REQ-RUL-01 先確定合法真實世界再挑選線索

案件必須先確定真實世界，再從世界中的事件及觀察選取線索。角色、場所、離散時間及移動約束必須完整，犯罪者必須在犯罪時刻實際位於犯罪場所，不能因需要某句線索而補造事實。

- 里程碑：M1
- 優先：必要

#### AC-RUL-01 基準世界合法且事實先於線索

- Given `reference_case` 的角色路徑、犯罪事件及 `world_rules`
- When 建立案件並逐項檢查路徑、犯罪與可靠線索來源
- Then 角色名單與場所符合資料限制，所有移動可在規定時間完成，犯罪符合到場規則；每條可靠線索都由既有真實世界支持，且選取線索不改變世界
- 驗證：自動

#### AC-RUL-02 非法移動不能成為可發佈案件

- Given `invalid_worlds.impossible_travel` 對基準世界的變更
- When 檢查該世界是否可用於出題
- Then 以資料中的 `expected_reason` 拒絕該世界，不產生可解或已證明的題目標記
- 驗證：自動

### REQ-RUL-02 唯一性只判斷兇手且分開不足與矛盾

判定必須涵蓋所有符合已知條件及可靠證據的可能世界。完整世界可以有未確定細節；只要所有可行世界的親自犯案者相同，就能支持唯一兇手。可行世界為空屬於矛盾，有不同兇手則屬於資訊不足。

- 里程碑：M1
- 優先：必要

#### AC-RUL-03 完整線索與不足子集有不同候選集合

- Given `evidence_sets.complete` 與 `evidence_sets.insufficient`
- When 分別依固定規則及各集合的可靠證據獨立判定
- Then 兇手候選集合及狀態分別等於資料中的 `expected_candidates` 與 `expected_status`；允許 `reference_case.additional_world_witness` 的不同未觀察行程，不要求整個世界唯一，也不得用 ground truth 私下消除仍可行的候選人
- 驗證：自動

#### AC-RUL-04 可靠證據矛盾不顯示為未找到答案

- Given `evidence_sets.contradictory` 的可靠證據
- When 判定可行世界與兇手候選
- Then 結果等於資料中的矛盾期望，顯示互相衝突的可靠證據，不列出推薦兇手，也不當作單純資訊不足
- 驗證：自動

### REQ-RUL-03 證詞可被反駁且不得冒充可靠事實

每句證詞均有發話者、命題及世界內真偽。發話是事實，內容不自動採信；只有獨立可靠證據能支持或反駁內容。偵查結論不得把未核對的說法直接視為事實，亦不得只因角色說謊就判其殺人。

- 里程碑：M2
- 優先：必要

#### AC-RUL-05 可靠記錄反駁說法而不造成假矛盾

- Given `testimony_checks.refuted_alibi` 的證詞與反證
- When 玩家將證詞和對應可靠記錄一起檢視
- Then 證詞標為被反駁並指出矛盾命題與來源；可靠證據集合仍等於資料中的一致狀態，說謊者身分本身不成為獨立的殺人證明
- 驗證：自動

### REQ-RUL-04 共謀掩護仍須唯一親自犯案者

變更輪允許資料中指定的兇手與掩護者共同編造不在場說法。掩護可造成錯誤方向，不能改變可靠記錄或允許多個親自犯案者；同一份結論需區別親自犯案及掩護責任。

- 里程碑：M3
- 優先：必要

#### AC-RUL-06 共謀說法不能使掩護者被當成另一兇手

- Given `coverup_case` 的真實事件、完整線索及共謀說法
- When 不預先讀取角色責任答案而獨立判定可行兇手
- Then 候選集合等於 `coverup_case.expected_candidates`；掩護者的在場限制仍有效，說法一致不增加其可靠性
- 驗證：自動

#### AC-RUL-07 揭曉分別說明殺人與掩護責任

- Given 玩家已完成 `coverup_case` 並主動選擇揭曉
- When 顯示案件結論與角色責任
- Then 兇手、掩護者及共同說法分別對應資料中的 ground truth，解釋如何反駁掩護，不將掩護者列為共同殺人答案
- 驗證：自動
