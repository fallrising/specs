# 品質與驗證邊界

所有基準及期望引用 [scenarios.yaml](../data/scenarios.yaml)；評測回報遵守[共同規則](../../../docs/model-challenge-evaluation.md)。

### REQ-QLT-01 獨立驗證的證據才可支持可解宣告

發佈前的驗證必須與產生真相的步驟分開，依完整規則與證據判定可能兇手，而非回傳內建答案。可採任何可核對方法，但需交付輸入、判定狀態、可行兇手及排除其他角色的證據；未執行或未完成不得標為通過。

- 里程碑：M1
- 優先：必要

#### AC-QLT-01 未完成驗證不會被包裝成唯一解證明

- Given `verification_outcomes` 中完成、未執行及未完成的情境
- When 決定案件是否能宣告可解並供玩家遊玩
- Then 只有完成且符合唯一兇手期望的案件取得可解標記；其他狀態顯示資料中的未驗證結果，不以 ground truth 或文件期望當作已證明
- 驗證：自動

### REQ-QLT-04 有界新案件生成

M2 能在 `generation_batch` 指定的世界範圍與嘗試上限內產生新的案件。每件都先有合法真實世界，再建立可取得的線索並獨立確認唯一兇手。只改顯示姓名、線索排列或案件標題，不算新的案件結構；不能只提供基準案例的重播按鈕。

- 里程碑：M2
- 優先：必要

#### AC-QLT-05 批次生成具有實質差異且可解

- Given `generation_batch` 的固定輸入、允許世界與多樣性門檻
- When 逐一要求產生新案件並從其可靠證據獨立判定
- Then 在嘗試上限內取得規定數量的合法可解案件，兇手、犯罪場所及案件特徵的多樣性均達門檻；每件的必要線索都可取得；若產生或驗證失敗就明示失敗，不用基準答案補成成功
- 驗證：自動

### REQ-QLT-02 相同案件可重現且不把冗餘線索誤當必要

相同案件識別、生成輸入及內容版本須能重現相同真實世界與線索命題；探索順序只影響取得紀錄。線索允許冗餘，除非資料明確聲明 minimal，否則不要求移除任何線索就出現多解。

- 里程碑：M2
- 優先：必要

#### AC-QLT-02 相同輸入重現相同世界與判定

- Given `reproducibility` 固定輸入與 `acquisition_routes`
- When 重建案件並使用不同取得順序完成探索
- Then 真實世界、可取得命題及最終候選集合均一致，取得順序差異可辨認且不改寫答案
- 驗證：自動

#### AC-QLT-03 移除冗餘證據不應錯報題目不合格

- Given `evidence_sets.with_redundancy` 及資料標記的冗餘證據
- When 移除該冗餘證據後重新驗證
- Then 候選集合仍與 `evidence_sets.complete` 相同且題目可維持合格；未宣告 minimal 的完整線索不得因仍為唯一兇手而被判失敗
- 驗證：自動

### REQ-QLT-03 共謀變更維持舊案件語義

第二輪增加掩護責任後，原案件的既知條件、證詞可信性、唯一性及線索取得規則保持一致。新增能力不能倒推出所有舊案都已有掩護者，也不能把舊案資訊不足改成猜測答案。

- 里程碑：M3
- 優先：必要

#### AC-QLT-04 舊案與新案使用各自明確的責任條件

- Given `regression_cases` 指定的基準案件、診斷集合及共謀案件
- When 完成共謀變更後逐一判定與重播探索
- Then 各案例仍符合其原有期望，沒有把掩護者規則隱含套入舊案；回報列出實際執行結果與未驗證項，不以新增功能畫面代替回歸證據
- 驗證：自動
