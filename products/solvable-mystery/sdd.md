# 業務 SDD：可解推理

本文件是業務邊界與需求索引，不定義技術架構、模組、介面或儲存格式。範圍來源為各 REQ 的里程碑欄；數值與實例來源為[情境資料](data/scenarios.yaml)。

## 業務詞彙與不變條件

| 詞彙 | 業務意義 |
| --- | --- |
| 真實世界 | 在選線索以前已確定的角色、路徑、事件、兇手及說法真偽；取得線索不會改寫它 |
| 可靠證據 | 案件規則承認為真且有世界內出處的觀察；可用於限制可能世界 |
| 證詞 | 角色確實說過某句話，不代表其內容為真；反駁的是命題，不自動把發話者定為兇手 |
| 可行世界 | 同時符合固定規則、案件既知條件及全部已採信可靠證據的世界 |
| 可行兇手 | 至少存在一個可行世界讓該候選人親自完成犯罪 |
| 唯一兇手 | 可行世界不為空，且其兇手投影只含同一個角色；其他未觀察行程可以不同 |
| 資訊不足 | 存在可行世界，但其兇手尚無法唯一確定 |
| 證據矛盾 | 不存在可行世界；不能用唯一答案、猜測或最接近答案掩蓋這個狀態 |
| 共謀掩護者 | 參與事前合意或提供虛假掩護的角色；與親自完成犯罪的兇手分開判定 |

案件既知條件包括角色名單、場所圖、時間範圍、犯罪方式限制及犯罪時間與場所。移動耗時以相鄰場所的定義累計；出發後到達前在途，不同時占據不同場所。犯罪需兇手與被害者在犯罪時刻同處犯罪場所；無遠端、延遲觸發或名單外犯案者。

## 業務流程與責任界線

先確認真實世界合法，再從其中挑選可取得證據，最後交由獨立驗證判定完整線索的兇手集合。生成者知道 ground truth 只能用來對照，不能代替獨立判定。獨立驗證逾時、能力不足或未執行都代表未驗證。

玩家的調查行為只揭露既有線索。線索的出處、命題及可靠性必須能回看；同一事實的重複呈現不應被計為不同支持力度。證詞的反證可以導致該說法失信，不會使本來一致的可靠證據自動變成矛盾。

未揭曉前，提交介面提供可觀察判定狀態及玩家使用的證據。主動揭曉後，才展示真實世界及逐項排除依據。玩家選對角色但未取得足夠證據，屬於猜中答案，不能標記「已證明」。

## 驗證狀態與變更邊界

資料中的候選集合是人工推導的草案期望，尚待獨立 solver 對整個有限規則空間驗證。基準世界只提供一個符合規則的見證，不等於已證明其他兇手全部不可行。M3 允許新增掩護者角色語義及配套線索，但保留唯一親自犯案者、證據回看與第一版案件的既有語義。

跨模型挑戰的輸入封存、兩輪變更、未完成回報及成本採[共同評測](../../docs/model-challenge-evaluation.md)；此產品只提供可觀察的業務判定。
