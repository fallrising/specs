# 資料、確認與恢復規則

所有數值、操作、期望及故障情境引用 [scenarios.yaml](../data/scenarios.yaml)。

### REQ-RUL-01 客戶端 KV 操作符合線性一致性

客戶端能寫入單一鍵並讀取值或明確的不存在結果。每份完整觀察歷史應可對應一個遵守即時先後的合法單機序列；重疊操作允許任一合法順序，未完成操作不得一律當成沒有生效。

- 里程碑：M1
- 優先：必要

#### AC-RUL-01 客戶端基準讀寫符合單機可見語義

- Given `baseline_case` 的初始資料、穩定叢集及順序操作
- When 客戶端逐項執行讀取、寫入及再次讀取，並保留實際呼叫與回覆
- Then 各讀值與成功結果符合資料期望且在指定期限完成，歷史可對應其單機序列；不存在的鍵以明確不存在結果呈現
- 驗證：自動

#### AC-RUL-02 已完成寫入後的新讀取不得回傳被覆蓋前值

- Given `small_histories.illegal_stale_read` 與 `illegal_reverted_value`
- When 判定有即時先後關係的操作結果
- Then 各歷史被辨認為非法並指出資料中的違反原因，不以事件畫面順序不同或最後有收斂為由接受
- 驗證：自動

### REQ-RUL-02 少數不得確認新寫入且已確認操作不可丟失

網路分割中的少數群組不得確認新的寫入，也不得用本地舊資料完成新的讀取。已確認操作必須保留在合法序列中；崩潰重啟後若沒有較新寫入覆蓋，讀取仍得到原值。有合法後續寫入時允許值改變，不要求每個節點隨時顯示同值。

- 里程碑：M1
- 優先：必要

#### AC-RUL-03 少數分割保持未確認並由多數維持合法結果

- Given `partition_case` 的固定分割、客戶端可達範圍及新請求
- When 依情境推進虛擬時間並分別觀察兩側結果
- Then 少數側新寫入沒有成功確認，多數側在自己的穩定條件下依資料期限完成；依 `minority_stale_read_probe`，多數側寫入完成後才從少數側發起的新讀取不得回傳舊值，只能保持未確認或不可用；整體已確認歷史維持線性一致，不把少數側自認 leader 當作成功依據
- 驗證：自動

#### AC-RUL-04 全體崩潰重啟保留確認結果並允許後續覆蓋

- Given `durability_case` 中先已確認的寫入及保留穩定儲存的崩潰重啟
- When 恢復穩定多數後讀取，再執行情境中的後續寫入及新讀取
- Then 首次恢復讀值及後續覆蓋值均符合資料期望；停機期間沒有服務不構成安全失敗，已確認操作不能從歷史中消失
- 驗證：自動

### REQ-RUL-03 同一請求重試維持意圖與既有結果

同一客戶端及請求識別只代表同一邏輯操作，重試不能再次施加已完成寫入，也不能把舊讀取變成新讀取。識別相同但操作、鍵或值不同時，明確拒絕且不改變任何既有結果。

- 里程碑：M2
- 優先：必要

#### AC-RUL-05 已完成操作的重試不回寫舊值或改變舊讀值

- Given `retry_cases.completed_write` 與 `completed_read`
- When 在較新寫入已確認後重送原請求，再以新請求讀取
- Then 重試回覆等於原結果，新讀取仍得到最新合法值；操作歷史將傳輸嘗試歸於原邏輯操作，不能把重試算成新寫入或新讀取
- 驗證：自動

#### AC-RUL-06 請求識別衝突與未確認重送有不同結果

- Given `retry_cases.conflicting_intent` 與 `pending_retry`
- When 分別重用已有識別及重送尚無客戶端確認的同一意圖
- Then 衝突意圖依資料拒絕且無資料變更；同一意圖延續原操作並只產生同一邏輯效果，不因回覆遺失產生另一操作
- 驗證：自動

### REQ-RUL-04 快照壓縮後仍可恢復落後節點與請求語義

快照可以涵蓋已確認狀態並壓縮其詳細日誌。落後節點重新連線或重啟後須取得足夠狀態恢復一致；壓縮不得遺失已確認資料或讓舊請求被誤當成新操作。

- 里程碑：M3
- 優先：必要

#### AC-RUL-07 落後節點跨越已壓縮區段後恢復可用

- Given `snapshot_case` 的落後節點、已確認寫入、快照及壓縮事件
- When 依情境恢復節點與穩定多數，並透過原落後節點發起新讀取
- Then 在資料期限內取得當前合法值，節點顯示已追上已確認狀態；恢復前不得把其舊值當作成功的新讀取結果
- 驗證：自動

#### AC-RUL-08 快照及重啟後重試仍是原操作

- Given `snapshot_case.retry_after_recovery` 的已完成請求與後續覆蓋
- When 快照壓縮、節點重啟及恢復後重送原請求
- Then 回覆仍為原結果且後續新讀值未回退，原請求關係不因日誌被壓縮而消失
- 驗證：自動
