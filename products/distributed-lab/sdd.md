# 業務 SDD：分散式實驗室

本文件只定義可觀察行為與教學邊界，不指定架構、共識模組、API、實作資料結構或快照格式。數值及操作歷史以[情境資料](data/scenarios.yaml)為準。

## KV 與線性一致性

每個實驗從資料中的初始鍵值開始。寫入原子地設定單一鍵；讀取回傳該鍵的值或明確的「不存在」。沒有多鍵交易承諾。

一份操作歷史合法，表示能將已完成的邏輯操作排列為符合單機 KV 的序列；某操作的回覆早於另一操作開始時，序列必須保持該先後。重疊操作可以採符合回傳值的任一先後。未完成操作可以不納入，或在合理位置補入其效果；不能只因客戶端逾時就假設它從未發生。

判定以操作的呼叫、回覆、鍵、值及同一請求關係為依據。重試回覆不被誤當成新的邏輯操作；分析用的已完成結果、未完成操作及重試關係都必須保留。

## 確認、保留與重試

| 詞彙 | 可觀察承諾 |
| --- | --- |
| 已確認寫入 | 客戶端收到成功結果；其效果已進入所有後續合法歷史必須尊重的序列 |
| 未確認操作 | 可能尚未生效，也可能已生效但回覆遺失；沒有成功或失敗的假定 |
| 不可用 | 這次嘗試沒有取得結果，不是邏輯操作的失敗結論；歷史分析視同未確認操作，同一請求可以重送並延續原操作 |
| 已確認操作不丟 | 故障及恢復不能令該操作從序列中消失；後續合法寫入仍可覆蓋同一鍵 |
| 同一請求 | 同一客戶端身分與請求識別對應同一意圖及同一邏輯操作，在實驗生命期內不重用 |
| 相同意圖重試 | 若已有結果就回傳原結果；未完成則延續同一操作，不因重送再次改變資料 |
| 不同意圖重用識別 | 明確拒絕，不能當作新操作執行，也不能覆蓋原結果 |
| 讀取重試 | 回傳原讀取的既有結果；需要最新值時必須建立新請求 |

對同一請求的後續傳輸只是在詢問原操作，故重試收到舊讀值不代表一次新讀取違反線性一致性。寫入重試亦不得在較新寫入後重新寫回舊值。以上語義跨節點崩潰、重啟及快照仍成立。

## 故障、安全與活性

節點成員固定，多數門檻依資料計算。隔離成少數的連通群組不能確認新的寫入；已在分割前確認的原請求可以回覆同一結果，但這不算確認新寫入。多數側是否可完成還需網路及公平執行條件。

不同領導世代可出現同時自認 leader 的節點。此時關心的是有沒有互相衝突的已確認歷史、少數側是否錯誤確認新寫入；不能以畫面上 leader 圖示的數量直接判定失敗。

延遲及重排只改變傳遞時間，複製不改變內容，丟棄不自動回滾邏輯操作。分割邊界的既有待送及新送訊息依資料規則丟棄，恢復連線不復活已丟棄訊息。崩潰停止節點工作；重啟保留穩定儲存，未落入穩定承諾的局部暫態可以消失。

安全承諾在所有允許故障下持續成立。活性只在成員中有多數存活、互相能可靠送達、客戶端能接觸該群組、處理及虛擬時間持續公平推進的穩定窗口內要求完成。沒有活性條件時，允許保持未確認或明確不可用，禁止虛假成功。

## 重播、分支與快照

重播固定初始情境、使用者操作、故障與已記錄的事件先後，重現同一可見歷史。反事實分支保留分支點之前的全部可見前綴及未完成操作，只改指定外部事件；原實驗保留不動。

快照及壓縮可減少保留的詳細日誌，但不能改變已確認資料、同一請求關係或可見操作結果。落後節點恢復後需與存活多數的已確認狀態一致，尚未補齊時不得用舊資料冒充合法的新讀取。

小型歷史的合法性可由列出的序列見證或反例人工核對，仍須由參考實作執行 AC 才能驗收產品。任意大歷史的檢查器若逾時只能給未判定，不能把結果提升成通過；本規格不要求特定檢查演算法。
