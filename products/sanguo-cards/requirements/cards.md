# 卡牌、陣營與牌組

卡池、主公與預組牌組的內容只寫在 [data/cards.yaml](../data/cards.yaml)。本檔只寫對那份資料的業務要求。

### REQ-CRD-01 卡池以資料檔為準
遊戲內每張卡的名稱、費用、攻、兵力、兵種、關鍵字與說明文字都來自 `data/cards.yaml`，不在程式裡另寫一份，方便調整平衡時只改一處。
- 里程碑：M1
- 優先：必要

#### AC-CRD-01 資料一致
- Given 項目所依據 specs SHA 的 `data/cards.yaml`
- When 遊戲載入卡池
- Then 每張 `collectible` 不為 false 的卡都可在遊戲中取得，所有欄位值與資料檔相同；資料檔沒有的卡不存在於遊戲中
- 驗證：自動

#### AC-CRD-02 改資料即生效
- Given 把資料檔中「步卒」的攻改為 2 後重新建置
- When 開局並打出步卒
- Then 場上步卒攻為 2，不需要改其他程式
- 驗證：自動

### REQ-CRD-02 M1 陣營：蜀、魏
M1 只做蜀與魏兩個陣營，各有主公與 11 種專屬卡，加上中立卡。
- 里程碑：M1
- 優先：必要

#### AC-CRD-03 陣營內容齊全
- Given M1 版本
- When 檢視可選陣營
- Then 只有蜀（主公劉備）與魏（主公曹操）可選；兩者的專屬卡與資料檔一致
- 驗證：自動

### REQ-CRD-03 預組牌組
新玩家不用組牌就能開打；M1 每個陣營一副固定的 30 張預組牌組。
- 里程碑：M1
- 優先：必要

#### AC-CRD-04 預組牌組合法
- Given 資料檔的 `shu_starter`、`wei_starter`
- When 依 `deck_rules` 檢查
- Then 兩副都是 30 張；同名不超過 2 張、武將不超過 1 張；只含本陣營與中立卡；不含 `collectible: false` 的卡
- 驗證：自動

### REQ-CRD-04 卡面資訊
玩家不看說明書也能從卡面判斷一張卡做什麼。
- 里程碑：M1
- 優先：必要

#### AC-CRD-05 卡面欄位
- Given 任一張部隊卡與任一張計策卡
- When 在手牌中檢視
- Then 部隊卡顯示名稱、費用、攻、兵力、兵種（圖示加文字）、關鍵字、說明文字、陣營；武將另有武將標記；計策卡顯示名稱、費用、說明文字、陣營
- 驗證：手動

### REQ-CRD-05 預組牌組平衡
任兩副預組牌組互打不應一面倒，讓選陣營是口味而不是答案。
- 里程碑：M1
- 優先：應有

#### AC-CRD-06 M1 對戰勝率
- Given 蜀、魏預組牌組，雙方都用 M1 電腦對手
- When 以 1000 個固定種子對戰（先後手各半）
- Then 任一方勝率在 40%–60%；結果表附在交付證據。超出範圍時以 SDD PR 調整 `data/cards.yaml`，不在項目內私改數值
- 驗證：自動

### REQ-CRD-06 吳、群雄陣營
M2 加入吳（主公孫權，火攻與水戰）與群雄（主公董卓，高攻高代價），各 11 種專屬卡與一副預組牌組。內容在 M2 開工前以 SDD PR 寫入資料檔。
- 里程碑：M2
- 優先：必要

#### AC-CRD-07 四陣營齊全
- Given M2 版本與已補齊的資料檔
- When 檢視可選陣營
- Then 蜀、魏、吳、群雄四個陣營都可選，各有主公、至少 11 種專屬卡與一副合法預組牌組
- 驗證：自動

#### AC-CRD-08 四陣營對戰勝率
- Given 四副預組牌組，雙方都用普通難度電腦
- When 每一組配對以 1000 個固定種子對戰（先後手各半）
- Then 每組配對任一方勝率在 40%–60%
- 驗證：自動
