# 實驗與觀察

案例與數值見 [scenarios.yaml](../data/scenarios.yaml)。

### REQ-EXP-01 完整流程與可追查圖表

使用者可選情境、開始、暫停、繼續、加速及結束，查看時間、價格、成交量、職業收入與現金分布。每個聚合結果可回到實際紀錄。無成交的時段明示無成交；商品估值和現金不同欄位且說明估值來源。
- 里程碑：M1
- 優先：必要

#### AC-EXP-01 從結果追到成交
- Given 已完成 `trade_case` 與 `money_case` 的世界
- When 由該時段的成交量與金錢變化開啟明細
- Then 可找到全部且僅有該時段已完成的交易、發行及回收，各明細加總等於概況，無成交時段顯示無成交
- 驗證：自動

#### AC-EXP-05 從空庫存完成生產交易消耗閉環
- Given `closed_loop_case` 的空庫存、角色資金及排定決策，沒有預先存在的商品或成交
- When 由開始推進到案例終點，實際執行採集、各階製造、兩次購買、任務發行、修理及最終消耗
- Then 所有里程事件均由合法動作產生，終點資金、庫存、發行、銷毀與成交數逐項符合 `expected`；可以逐筆追查完整鏈，禁止直接載入預造終點或圖表代替執行
- 驗證：自動

### REQ-EXP-02 保存、恢復與重播

使用者在完整事件之間保存，恢復後保留進行中的工作、託管商品、待發生義務及已完成業務結果。相同情境版本、初始條件、外生輸入與操作，關鍵狀態及經濟紀錄一致；不要求圖形像素一致。
- 里程碑：M2
- 優先：必要

#### AC-EXP-02 工作途中恢復
- Given `restore_case`：`production_case` 在工作開始後、完成前保存，且世界中另有尚未到期掛單
- When 分別不中斷執行與從保存狀態恢復到相同終點
- Then 兩者都符合 `restore_case.expected_at_end`，現金、庫存、掛單、製成品、已結算業務及剩餘義務一致，沒有重複扣料、領獎或成交
- 驗證：自動

#### AC-EXP-03 拒絕損壞或不相容存檔
- Given 一份被截斷、缺少必要世界資訊或版本不支援的保存資料
- When 使用者要求載入
- Then 明確說明無法載入且保留目前世界，不部分套用、不假裝成功或悄悄重置
- 驗證：自動

### REQ-EXP-03 干預與反事實分支

使用者可從同一歷史狀態建立兩個分支，修改資料允許的供給或政策參數。比較顯示共同起點、共同外生條件、差異設定及後續結果；原歷史不變。當設定沒有差異時，不得產生不同經濟結果。
- 里程碑：M2
- 優先：必要

#### AC-EXP-04 同起點的政策比較
- Given `intervention_case` 的共同起點、固定外生條件及 A／B 採集參數
- When 分別執行到相同終點，再以兩個相同 A 設定重跑
- Then A／B 在介入前狀態一致，介入後採集量遵守各自參數且差異可查；兩個 A 的 `regression_digest` 逐項相同，原歷史不變；不預設最終市場價格方向
- 驗證：自動
