# 品質與解讀

數值見 [scenarios.yaml](../data/scenarios.yaml)，比較方法見[共同評測規格](../../../docs/model-challenge-evaluation.md)。

### REQ-QLT-01 明確拒絕非法情境

開始前檢查情境的價格、數量、配方引用、角色數及期間範圍。非法情境必須指出欄位與原因，既有世界不受影響；不能靠忽略欄位或自動改成有利數值通過。
- 里程碑：M2
- 優先：必要

#### AC-QLT-01 非法值不啟動
- Given `invalid_cases` 的任一非法設定及一個已暫停的有效世界
- When 嘗試啟動該非法情境
- Then 顯示對應原因、不啟動新模擬，原世界現金、庫存與時間不變
- 驗證：自動

### REQ-QLT-02 基準規模的有界執行

在事前固定的參考設備上完成 baseline 期間，同時保留完整帳務檢查結果。量測依 performance 的暖機、重複、計時起訖及門檻；另記記憶體與互動回應。設備未固定或測量不完整則是未驗證，不是通過。
- 里程碑：M2
- 優先：必要

#### AC-QLT-02 基準完成與停止
- Given 已事前登記的設備、資料版本及 `performance` 條件
- When 跑完全部基準重複並在指定檢查點提出暫停
- Then 每次完整跑完且帳務正確，執行時間及暫停延遲滿足資料門檻；提供所有原始結果，不只選最快一次
- 驗證：手動

### REQ-QLT-03 結果可讀且不誤導

繁體中文介面明示世界時間、模擬假設、單位、無成交狀態與估值依據。使用者能從異常指標找到實際經濟紀錄，不能用生成敘述取代紀錄。
- 里程碑：M2
- 優先：必要

#### AC-QLT-03 從概況完成解讀任務
- Given `observation_tasks` 及已產生的公開案例結果
- When 評閱者只操作介面完成各項任務
- Then 每項均能定位正確紀錄、區分現金與估值並辨識無成交時段；owner 依任務結果確認資訊可理解，失敗項逐條記錄
- 驗證：人工確認
