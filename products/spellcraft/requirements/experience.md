# 編輯與試驗體驗

資料、試驗目標與預期術式見 [scenarios.yaml](../data/scenarios.yaml)。

### REQ-SPX-01 編輯、撤銷與錯誤定位

玩家可建立、選取、移動及刪除節點，設定允許的延遲，連接合法段落，並撤銷或重做最近操作。尚未完整的術式可留在編輯畫面，但試射入口必須說明阻擋原因並指向問題節點或連線。成本預覽隨合法術式更新；畫布節點移動不改變術式語意。鍵盤可完成與滑鼠相同的必要編輯動作，錯誤提示不能把已建立的術式清空。

- 里程碑：M1
- 優先：必要

#### AC-SPX-01 修正錯誤而不遺失術式
- Given `cases.editing` 的合法術式及預定修改序列
- When 分別用鍵盤與滑鼠製造非法組合、修正、撤銷、重做並移動畫布節點
- Then 每步術式、成本、可否試射及錯誤定位符合預期；撤銷恢復原節點與設定，純位置變化不改變結果
- 驗證：手動

### REQ-SPX-02 可解釋試驗與逐步觀察

每張 `trials` 試驗卡顯示目標、起始條件與成功限制。玩家可試射、暫停、逐事件前進、選取事件及重置。因果紀錄列出來源施法、節點或反應、目標、傷害、狀態前後、法力及預算變化；被抑制事件也列原因。選取紀錄須標示對應節點與目標，目標已消失時仍可看其識別與結果。重置回到試驗初始法力、生命值、位置與狀態並取消待發效果，舊紀錄保留為唯讀。

- 里程碑：M1
- 優先：必要

#### AC-SPX-02 因果逐步可追查
- Given `cases.trace` 的導電與命中子段紀錄
- When 暫停、逐事件前進並選取每個直接、間接及受抑制事件
- Then 每次只前進選定事件順序中的下一項，生命值與狀態符合檢查點；畫面能指回來源及目標，並顯示每次預算變化與抑制理由
- 驗證：自動

#### AC-SPX-03 新玩家完成試驗並可重置
- Given 符合 `experience_trial` 的新玩家只使用產品內說明
- When 完成指定試驗、說明選定反應原因，並在有延遲投射物與燃燒時重置
- Then 完成比例與時間符合該資料，玩家可指出來源與結果；重置後符合 `arena.initial_state`，先前等待及燃燒不再作用，舊紀錄仍可辨識為唯讀
- 驗證：手動

### REQ-SPX-03 命名術式保留

玩家可命名儲存目前術式，並在重新開啟瀏覽器後載回相同節點、順序、參數與名稱。不合法草稿可以儲存但必須保持草稿標示與試射禁用；不能為了載入成功而默默刪除不認識的節點。覆寫既有名稱須先看到所替換術式並明確確認，取消覆寫不改變原存檔。

- 里程碑：M2
- 優先：必要

#### AC-SPX-04 儲存重開與取消覆寫
- Given `cases.saved_spells` 的合法術式及非法草稿
- When 命名儲存、關閉再重開，之後嘗試同名覆寫並取消
- Then 名稱、節點、參數、成本與合法性等於原內容；重開的合法術式結果相同，非法草稿仍不可試射；取消後原內容不變
- 驗證：手動
