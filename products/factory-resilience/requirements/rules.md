# 排程與物料規則

數值與期望唯一來源為 [scenarios.yaml](../data/scenarios.yaml)。這些 AC 是待參考實作確認的草案。

### REQ-FR-01 明確有界的場景

接受資料目錄內的機種、物料、資源及訂單，並以 `limits` 為界（含每張訂單的數量上限）。場景不合法時須在開工前指出原因，不得截斷資料或默默忽略訂單。
- 里程碑：M2
- 優先：必要

#### AC-FR-01 完整邊界場景
- Given `bounded_demo` 的完整訂單、資源、配方與初始庫存
- When 載入並執行其 `sequential_witness`
- Then 所有訂單可合法交付，目錄及訂單數均與資料一致，完工時間符合該 witness，且標示可行、最優性未知
- 驗證：自動

#### AC-FR-02 超出上限與未知材料
- Given `invalid_scenarios` 的超額訂單或未知物料變體
- When 嘗試載入
- Then 拒絕該場景並指出違規欄位，既有場景與庫存不變
- 驗證：自動

### REQ-FR-02 工序前後關係與容量互斥

工序必須遵循配方順序、搬運完成與資源容量；占用區間採半開區間。非法計畫不能進入執行，衝突須指向實際工序與資源。
- 里程碑：M1
- 優先：必要

#### AC-FR-03 可行排程逐事件成立
- Given `mini` 初始狀態與 `feasible_witness`
- When 逐事件執行至最後交付
- Then 每次開工均滿足先後關係、到貨與容量，訂單完工時間及最終交付符合 `expected`
- 驗證：自動

#### AC-FR-04 明確攔截不合法排程
- Given `mini.invalid_plans` 中的容量重疊與未到貨開工案例
- When 檢查或要求執行該計畫
- Then 分別顯示資料所列的衝突資源與工序，禁止執行，且不扣料
- 驗證：自動

### REQ-FR-03 物料轉換與質量守恆

預排不扣料；開工才投入、完成才產出。運送中的物料仍屬工廠，但不可被其他工序使用。全場可用、加工中、運送中、廢料與已交付質量的總和必須等於初始質量加上明列補料；本場景沒有隱含補料。
- 里程碑：M1
- 優先：必要

#### AC-FR-05 全流程材料帳
- Given `mini` 的配方、質量表與初始庫存
- When 依 witness 暫停在 `ledger_checkpoints` 的各時間
- Then 可用材料、加工中投入、搬運中材料及已交付材料符合各檢查點，全程總質量不變，最終未完成品與廢料符合期望
- 驗證：自動

### REQ-FR-04 開始前故障與有限重排

已知故障期間不可新開工；故障區間為半開區間，故障與修復時間在故障開始時才得知（`fault_semantics`）。使用者提出重排後，系統須在已公布場景上限內提出完整可行計畫，保留已完成、已開始及已搬運的事實，只調整尚未開始工序。結果可以較原方案更差，但須符合案例的公開接受門檻並列出交期影響；不必與 witness 相同，不能聲稱找到未經證明的最優解。
- 里程碑：M2
- 優先：必要

#### AC-FR-06 故障與同時開工的順序
- Given `before_start_fault` 與其受影響機器，原計畫安排工序在故障開始時開工
- When 故障生效並載入 `replanned_witness`
- Then 該工序不會在故障期間開工，既有完成紀錄保持，後續交付時間與逾期符合期望，且重排不超過場景上限
- 驗證：自動

#### AC-FR-09 系統提出故障後可行方案
- Given `before_start_fault` 的原計畫與故障事件，使用者未提供後續排程
- When 使用者要求系統重新安排
- Then 系統提出並可執行完整方案，保留已發生事實、滿足所有資源與物料限制，結果符合 `generated_plan_acceptance`；可與 witness 不同，但須附指標、下界與最優性未知標記
- 驗證：自動

### REQ-FR-05 加工中斷、取消與重送的材料責任

加工中故障或取消適用 `interruption_policy`：失敗的嘗試無產出，投入只按配方回收，其餘入廢料帳；修復後重新開工需重新投入。取消未開工訂單釋放預排需求；搬運中取消先完成搬運再終止；已交付不可取消。相同回報重送不得產生第二次效果。本版沒有回收表的中斷（裁切加工中的故障或取消、搬運中的載具故障）一律依 `interruption_policy.unsupported` 明確拒絕且不改變狀態，不自行補出回收規則。
- 里程碑：M3
- 優先：必要

#### AC-FR-07 中途故障、修復與重作
- Given `during_processing_fault` 的備料、故障、回收表與重排 witness
- When 加工開始後故障，先以 witness 核對回收及重作，再由相同故障狀態要求系統自行重排並完成交付
- Then 失敗嘗試不產生成品，回收與廢料符合 `expected_after_fault`；witness 符合 `expected_final`，系統方案符合 `generated_plan_acceptance`，兩者修復後均重新扣料且保持總質量守恆
- 驗證：自動

#### AC-FR-08 取消與重複回報邊界
- Given `cancellation_cases`、`duplicate_reports` 與 `unsupported_interruptions` 的各獨立案例
- When 在指定時點取消，或重送相同與衝突內容的回報
- Then 各案例的可用物料、廢料、訂單狀態與生效次數符合資料；衝突回報、已交付取消與未支援的中斷被拒絕且狀態不變，取消訂單沒有後續產出或重複交付
- 驗證：自動
