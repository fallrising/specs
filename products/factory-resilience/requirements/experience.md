# 操作與結果解釋

情境與數值來源為 [scenarios.yaml](../data/scenarios.yaml)。

### REQ-FX-01 從訂單到交付的完整操作

使用者可檢視訂單、安排工序、看衝突、執行、暫停、逐事件前進及重設。立體場景、時間表、材料與訂單詳情必須對應同一模擬時間；鏡頭操作不能改變生產。
- 里程碑：M1
- 優先：必要

#### AC-FX-01 完整使用路徑
- Given 初次開啟 `mini`
- When 使用者完成 `interaction_walkthrough`，包含一次無效安排的修正與最後交付
- Then 可僅靠畫面辨認衝突原因與等待中的訂單，完成合法計畫並看到交付結果；重設恢復原始庫存與未開始狀態
- 驗證：人工確認

#### AC-FX-02 視圖與生產狀態一致
- Given `mini` 在任一 `ledger_checkpoints` 暫停
- When 轉動鏡頭、選取工序與切換時間表
- Then 選取的訂單、工序、位置與時間一致；模擬時間、材料與結果不變，不將畫面動畫完成誤認為工序完成
- 驗證：手動

### REQ-FX-02 可重算而不混淆的績效指標

顯示各訂單交期與交付時間、總逾期、完工時間、在製品時間平均與各資源閒置率，使用 `metric_definitions`。缺少交付的方案標示未完成，不以零完工時間冒充改善。沒有可用時間的資源閒置率顯示不適用。
- 里程碑：M1
- 優先：必要

#### AC-FX-03 小型場景的指標 oracle
- Given `mini.feasible_witness`
- When 所有訂單完成並開啟結果
- Then 逐項指標及觀察窗口與 `mini.expected.metrics` 一致，且可追溯至交付時間與資源占用區間
- 驗證：自動

#### AC-FX-04 未完成與無可用時間
- Given `metric_edge_cases` 的未交付方案與整段停機資源
- When 查看比較結果
- Then 未交付方案明示未完成及待交付數，整段停機資源顯示不適用，不產生零值改善或非有限數字
- 驗證：自動

### REQ-FX-03 說清楚結果的證據範圍

方案比較列出合法性、每項指標、下界及證據標籤；可行解與最優證明不得混用。提示須能連回造成等待或逾期的已知限制。
- 里程碑：M2
- 優先：必要

#### AC-FX-05 故障前後的可解釋比較
- Given `mini` 與 `before_start_fault` 的兩份 witness 和各自的下界
- When 並排比較結果並選取受影響訂單
- Then 顯示各自窗口、交付與逾期變化，能指向故障占用區間；兩個 witness 均不得標為已證最優
- 驗證：人工確認
