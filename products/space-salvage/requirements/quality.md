# 品質與證據

案例與測量條件見 [scenarios.yaml](../data/scenarios.yaml)；共通比較與證據規則見 [共同評測](../../../docs/model-challenge-evaluation.md)。下列為未經參考實作鎖定的預期 AC，不是實測結果。

### REQ-SSQ-01 業務重播與重新開始

任務紀錄須可唯讀重播已接受的切割、來源與隔離變更、回收批次及結束事件，並顯示事件順序、相關模組與拒絕原因。從固定初始船體重播相同已提交事件，必須得到相同結構群組、供電集合與結算；不要求逐幀漂浮軌跡相同。重播不能更改原任務收益。重新開始必須清除前次切口、隔離、回收與計時，建立獨立的新任務。

- 里程碑：M2
- 優先：必要

#### AC-SSQ-01 相同事件得到相同結算
- Given `replay.canonical_run` 的初始內容及已提交業務事件
- When 完成任務後依 `replay.repeat_count` 重播，並檢視被拒絕的事件
- Then 每次最終集合與結算都等於案例預期，拒絕事件維持未生效；原任務累計金額不變，事件能指出原因
- 驗證：自動

#### AC-SSQ-02 新任務沒有舊成果
- Given 上一任務已切割、隔離並回收且正在檢視重播
- When 重新開始
- Then 模組、接點、來源、隔離、計時與金額全部回復 `mission.initial_state`，新任務與原重播紀錄可區分
- 驗證：自動

### REQ-SSQ-02 視覺辨識與可重現效能

畫面必須表現船體輪廓、可切接點、艙門、回收艙與安全碼頭的空間關係；照明、材質與效果不得遮蔽必要提示。視覺按 `visual_checks` 每項確認。效能依 `verification_profile` 的設備、作業系統、瀏覽器完整版本、視窗、像素比、畫質、電源模式、固定巡覽及樣本期間測量；任何必填欄未鎖定即不能宣稱通過，也不能用較輕場景替代。測試前保留原始紀錄及場景畫面。

- 里程碑：M2
- 優先：必要

#### AC-SSQ-03 美術可辨識檢核
- Given 使用待批准的構圖參考與 `visual_checks` 指定視角、狀態及亮度條件
- When owner 依清單逐項比較正常、低亮度及關閉色彩提示的畫面
- Then 每項皆有通過或不通過紀錄；接點可辨、物件無明顯穿透、文字可讀、回收艙界線清楚且必要效果不遮擋目標，全部通過才可接受
- 驗證：人工確認

#### AC-SSQ-04 固定場景效能
- Given `verification_profile` 已鎖定所有必填欄，使用完整船體與指定活動群組
- When 按該資料暖機、巡覽並重複測量
- Then 各次載入時間及畫面時間百分位都符合該資料門檻，附設備、版本、解析度、場景及原始紀錄；沒有資料時標示未測而非通過
- 驗證：手動
