# 玩家體驗

任務、數值與檢核資料見 [scenarios.yaml](../data/scenarios.yaml)。

### REQ-SSX-01 完整任務與可理解的結算

玩家由安全碼頭開始，必須能依序進入船體、隔離供電、切割、牽引、回收並正常撤離。正常撤離且已回收金額達 `mission.target_value` 才標示完成；未達目標為提前撤離。達時間上限即安全返回並標示逾時。暫停、操作說明及失去操作焦點期間停止任務計時。結算列出任務結果、已回收模組、金額、有效操作時間及未回收目標，不能只顯示分數。

- 里程碑：M1
- 優先：必要

#### AC-SSX-01 首次遊玩完整流程
- Given 符合 `experience_trial` 條件、未看過本產品的受測者使用新任務
- When 只依產品內說明完成任務，並記錄操作、暫停與結算
- Then 達到該資料的完成比例與有效時間窗口，成功者都實際經過完整流程；另依 `cases.endings` 確認提前撤離與逾時不標成完成，暫停時間不計入任務
- 驗證：手動

### REQ-SSX-02 斷電撤離與脫困

門斷電時仍能在兩側使用手動解鎖，不需要金額、工具耗材或已回收的部件。`ship.protected_modules` 與受保護接點不能被回收或切除。任何時候都能暫停並選擇緊急返回；確認後回到安全碼頭結束任務，保留已回收成果並標示緊急撤離。選取卡住的群組不能禁用選單、手動門或緊急返回。緊急返回不能用來把未回收物轉成分數。

- 里程碑：M1
- 優先：必要

#### AC-SSX-02 無電與卡住仍可離場
- Given `cases.escape` 的斷電、門關閉及回收艙被未結算物阻擋情境
- When 分別手動開門正常離場、取消緊急返回及確認緊急返回
- Then 手動離場可完成，取消後狀態不變，確認後必回安全碼頭；結算僅保留案例中已回收成果，沒有不可結束的狀態
- 驗證：自動

### REQ-SSX-03 操作前後的資訊可讀

指向接點時顯示可切與否、帶電原因、預期分離群組；選取群組時顯示質量、容積與回收價值。固定、可移動、帶電、斷電、回收處理中與已回收都須有文字或形狀提示，不能只靠顏色。拒絕操作應保留選取並說明下一個可行操作，例如隔離電源或拆小群組，不要求玩家重讀文件。

- 里程碑：M1
- 優先：必要

#### AC-SSX-03 能據提示選出下一步
- Given 使用 `visual_checks.state_samples` 的各種狀態且關閉色彩提示
- When owner 逐項檢視接點、群組及被拒絕的回收操作
- Then 每項都能從畫面讀出狀態、拒絕原因及可行下一步；預覽群組與實際分離一致，沒有靠顏色才能區分的必要資訊
- 驗證：人工確認
