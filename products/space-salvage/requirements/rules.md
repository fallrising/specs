# 拆解與回收規則

本文數值、模組與預期集合均引用 [scenarios.yaml](../data/scenarios.yaml)。

### REQ-SSR-01 接點切割與結構分離

只能切 `ship.joints` 已列出的可切接點；受保護接點與其他表面不接受切割。成功切割永久移除本任務中的該接點，重複操作不改變狀態。仍經完整接點連到 `ship.anchor` 的模組固定；其餘依剩餘接點形成可移動群組。切割預覽必須顯示此次會分離的群組，不能隨機破碎。

- 里程碑：M1
- 優先：必要

#### AC-SSR-01 固定船體與分離集合
- Given 使用 `ship` 的完整船體且電源已關閉
- When 依 `cases.detach` 切開指定接點
- Then 初始模組數符合 `ship.module_count`，分離集合、仍固定集合及剩餘接點等於該案例預期，沒有產生未定義碎片
- 驗證：自動

#### AC-SSR-02 無效與重複切割
- Given `cases.cut_rejection` 的受保護接點、已切接點及非接點表面
- When 分別嘗試切割
- Then 顯示案例列出的拒絕或已完成原因；接點、群組與金額維持不變
- 驗證：自動

### REQ-SSR-02 供電與活線拒絕

模組帶電的必要條件是仍存在於任務中，且可經有效、未隔離的供電路徑到達已開啟的來源；來源即使與錨點分離也不自動停機。M1 路徑為 `power.baseline`。結構接點若綁定電路且任一端帶電，切割必須拒絕，先隔離再切才可成功。切割成功同時斷開該接點綁定的電路。來源開關及隔離開關不消耗金額，狀態變化須在下一次可接受操作前反映。

- 里程碑：M1
- 優先：必要

#### AC-SSR-03 活線切割拒絕
- Given `cases.live_cut` 的來源與隔離開關狀態
- When 先嘗試指定活線接點，再關閉來源並重試
- Then 首次依案例拒絕且無結構變化；重試成功，帶電集合與分離結果等於案例預期
- 驗證：自動

#### AC-SSR-04 支路隔離與門斷電
- Given `cases.branch_isolation` 的樹狀供電
- When 關閉案例指定的支路開關
- Then 僅案例列出的模組斷電，其他供電維持；門顯示斷電且仍提供手動開門；單純隔離不改變結構群組
- 驗證：自動

### REQ-SSR-03 低重力牽引

牽引只能選取未回收、已分離且符合 `handling` 距離與質量限制的完整群組，不能暗中替玩家切開接點。牽引使群組朝指向的停靠位置移動，速度不超過上限；放開後在無碰撞的區域維持當時直線速度，制動操作使選取群組停止。超距、超質量或固定群組必須拒絕並告知原因。碰撞不得穿越回收艙牆面；本稿不要求角動量或精密彈性碰撞。

- 里程碑：M1
- 優先：必要

#### AC-SSR-05 牽引、放開與制動
- Given `cases.tether` 的合法群組及各種不合法選取
- When 按案例順序牽引、放開、觀察位移並制動
- Then 合法群組符合距離、速度與漂移容許值；制動後速度符合停止條件；每項不合法選取保持原狀並顯示指定原因
- 驗證：自動

### REQ-SSR-04 原子回收與單批容積

群組必須完全位於回收艙內、已脫離固定船體、全體可回收且未經結算，才可確認回收。群組容積是其模組 `volume_units` 相加，必須符合 `intake.capacity_units`；容量不夠或任何模組不合格時整批拒絕。通過後整批金額一次加入累計，該批模組離開場景，艙容量恢復可供下一批使用。相同模組 ID 在同一任務不得再次入帳，處理中不可再次接收同批確認；超量批次可以退出後再切小，不會被吞掉。

- 里程碑：M1
- 優先：必要

#### AC-SSR-06 超容積後仍可拆小
- Given `cases.intake_oversize` 的已分離群組完整放進回收艙
- When 先確認回收，再依案例退出、切開及回收子群組
- Then 超量批次保持完整且不加分；子群組依案例金額入帳，剩餘模組可繼續操作，容量不累積占用
- 驗證：自動

#### AC-SSR-07 回收不重複入帳
- Given `cases.intake_once` 的合法批次
- When 依案例在處理中、完成後及重播時重複提交該批次
- Then 累計金額、已回收模組集合與接收次數均等於案例預期；沒有部分入帳或複製模組
- 驗證：自動

### REQ-SSR-05 環路與繞路供電

M3 使用 `power.loop_extension` 加入既定供電路徑，路徑不代表新的結構接點，也不模擬線纜拉力。供電仍依來源可達性判斷：只切斷某條路徑不得把仍可經替代路徑到達來源的模組誤判為斷電。玩家可以分別隔離繞路或關閉來源；任何環路不得讓操作永久等待。既有樹狀案例維持原結果。

- 里程碑：M3
- 優先：必要

#### AC-SSR-08 替代路徑保留供電
- Given `cases.power_loop` 的來源及替代路徑
- When 依案例先關閉原路徑、再關閉替代路徑，最後恢復原路徑
- Then 每一步帶電集合及活線拒絕結果等於案例預期；操作可結束；停用擴充後樹狀案例結果不變
- 驗證：自動
